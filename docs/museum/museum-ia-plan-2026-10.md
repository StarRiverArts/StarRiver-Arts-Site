# StarRiver Museum｜網站定位與資訊架構規劃

- **日期**：2026-10-08
- **文件性質**：內部規劃紀錄；不是對外宣言、已發布規格或可直接上站的文案。
- **名稱**：暫用 **StarRiver Museum**。正式名稱、品牌命名與對外副標尚未確定；現階段不為了命名阻礙內容架構。
- **狀態**：核心方向已在對話中確認；導覽文字、內容分類與實作細節仍可調整。
- **適用範圍**：`StarRiver-Arts-Site` 之 Museum 入口與內容管理；不直接重定義 Studio / ProjectT。
- **依據**：2026-09 至 2026-10 Museum 討論、2026-10-08 網站現況檢視、既有 `docs/CONTENT_SSOT.md`。如與現有公開文字衝突，以使用者較新的明確決策為準；此文件的「候選方案」不構成核准的公開文案。

## 1. 方向：更少承諾，更多空間

Museum 是持續發展中的策展、創作、觀看與交流平台；**不等於單一 VRChat world，也不只是等待 VR 館舍完工的預告網站**。虛擬館舍是其中重要的空間載體與可能的創作成果，但不是所有內容的必經容器。

Museum 可以容納：
- 跨媒介展覽、藝術作品、互動體驗、概念呈現；
- 文化、人文、社群故事、觀察、訪談、觀點與推廣；
- 研究、設計實驗、資料、方法、問題與尚未形成結論的探索；
- 活動、合作、參與和其他未來逐漸出現的形式。

**不要把「研究」當成所有內容的身份**：研究是方法，推廣是目的，社群是參與關係，文章是格式，展覽是呈現／策展單位。這些軸線可以交叉，不應被強迫排成互斥的固定分類。

**不要提前承諾題目、年度展期、開館時間、成果、平台或數量**。已有興趣和候選主題不等於對外發表的常設任務；個人創作與臺灣／VRChat 文化內容也不必強行統合成單一敘事。

## 2. 建議第一層結構（功能方向已確認，名稱保留彈性）

```text
StarRiver Museum（暫名）
├── Exhibitions         展覽、展品、作品與觀看入口
├── Explore / Editorial 探索、文章、文化、社群、研究及推廣
├── Venue               虛擬館舍、建築、庭園、空間體驗
└── About               簡短定位與聯絡入口
```

- **Exhibitions**：依展覽／作品組織，不依特定技術或單一場館組織。展覽可在 Web、VR、獨立 worldspace 或其他媒介呈現。
- **Explore / Editorial**：此層的**功能**已確認，**導覽名稱未定**；`Explore`、`Articles`、`Journal` 等只是候選。可包含文化文章、社群紀錄、觀點、研究、宣傳推廣、創作筆記；初期不必分出所有次分類，更不可要求每篇文章都有研究設計。
- **Venue**：專門介紹 VR 虛擬館舍及其場址、建築、庭園、公共空間、展廳與外部世界關係。設計中的方案、版本與研究應標示狀態，不當作完工事實。
- **About**：簡短回答「這是什麼／能在這裡看到什麼／網站與 VR 場館的關係」。Contact 可以留在此處或頁尾，不必佔用重要的第一層入口。
- 活動／Programs 如有穩定內容可作為獨立聚合或跨區索引；目前不預先要求一個空白的一級區塊。

以上是**資訊角色**，而不是要求每種內容都要有完整的資料庫、獨立頁面或新設計語言。

## 3. 核心媒介原則：網頁也是展覽的場地與作品

網頁可以同時是：
1. Museum 的資訊入口／展覽目錄；
2. 具有自己的版型、節奏與互動的獨立展覽；
3. 另一檔展覽中的單件作品。

允許的形式包含單頁展覽、microsite（多頁小站）、外部獨立網站、VRChat 主館、外部 VRChat worldspace、混合形式、未來新增媒介。

**將「展覽的目錄資訊」與「觀眾真正觀看的展覽本體」分離**。Museum 提供策展關聯、基本 metadata、導覽與可追溯記錄，但不強制展覽本體套用 Museum 導覽列、CSS、頁面殼或 CMS 範本。單頁作品也可直接由展覽卡片進入，不必多加一個無效過場頁。

例：
```text
Exhibitions Index
  ├── 展覽 A → 展覽資訊頁（選用） → 自有單頁 HTML 展覽
  ├── 展覽 B → 獨立 microsite / 多章節網站
  ├── 展覽 C → VRChat Museum / 外部 worldspace
  └── 展覽 D → 外部站點／混合媒介
```

**展覽（Exhibition）、作品（Work / Exhibit）、內容（Article / Research）、空間（Venue / Worldspace）、媒介（Medium）是不同實體。** 
- 一個展覽可包含多件作品，也可本身就是一個不可拆的網頁互動體驗。
- 一件作品可參與多個展覽。
- 一篇文章可連結零到多件作品、零到多檔展覽。
- 同一主題可能同時有展覽、研究、訪談或社群活動，互相連結但不互相從屬。

## 4. 初步內容模型（為未來實作提供方向，非立即資料庫規格）

**Exhibition / Experience**
- 穩定識別碼、標題、摘要、狀態（planning / current / archived 等，具體值待定）
- 創作者／策展者、日期或展期（有才填）、媒介（可多值）
- 入口 URL（Web / VR / 外部，零至多個）、展覽所在地／體驗方式（選填）
- 關聯作品、文章、研究、活動（皆選填）
- 可不要求實體展廳、固定週期、固定件數或獨立詳情頁

**Editorial / Explore**
- 標題、作者／來源、日期、格式或內容性質
- 可選主題／標籤、引用資料、相關作品／展覽／活動
- 說明其為評論、個人觀察、社群記錄、研究報告、推廣或其他內容；不同類型不強制套用同一種證據門檻
- 研究內容可以記錄 open question / limitations / methodology，但不將這些欄位強迫套用到所有文章

**Venue**
- 發展狀態、概念與版本、空間介紹、參觀入口（有才填）
- 建築／庭園／常設與輪替空間／外部 worldspace 的關聯
- 建築本身可作為敘事與作品；對動線和 UI 的原則須留在空間設計層處理，勿以網站功能取代空間設計的問題定義

## 6. 實施順序（規劃，不是執行授權）

1. **資訊盤點與用語決策**：維持 StarRiver Museum 暫名；確認 Explore / Editorial 的導覽名稱與最小必要分類。
2. **首頁資訊架構**：讓 Museum 首頁承載 Museum，而非被 `Preseason` 取代；保留現有公開項目的可進入性。
3. **展覽系統**：建立媒介中立的展覽索引、選用的詳情頁與直連獨立展覽機制；不先設複雜 CMS。
4. **內容層**：讓一般文章、人文內容、推廣、社群與研究共存；先以低維護成本發布真實內容，再視量增加分類。
5. **Venue 層**：公開適量且經確認的建築／庭園／VR 空間構想，不公開尚未定案的規格為事實。
6. **網站整合與驗證**：保留有效舊 URL、支援繁中與英文、保護 CMS 插入點和現有站台契約，依 repo 規範重建索引及檢查，再經使用者批准後部署。

- 對外宣言與策展主張的精確語言；不得把本文件的內部推理直接搬上首頁。
